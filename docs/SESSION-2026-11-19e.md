# Session 2026-11-19 (evening): Wi-Fi on MT6785, Safari drawing, Bold Text, idle CPU

## Wi-Fi: working (joins, browses)

`kernel/bsd/dev/begonia_wifi.c` came from the MT6781 ("viva") port and kept MT6781's hardware values: PMIC MT6358
rail offsets (on this phone's MT6359 those are other registers, among them VM18_CON0, the memory rail), MT6781 GPIO
pins and SPM registers. It ran at every boot (`begonia_wlan_init` powers Wi-Fi on). Fixed in order:

| commit | what |
|---|---|
| 3635cab | MT6785's own platform layer (mt6785.c, clk-mt6785-pg.c): SPM CONN 0x10006320, status 0x10006160/164, CCIF4 bit 28, CON_PWR_ON 0x10003438, A-die pins 0x10005430/440 + 0x11ea0000, chip id 0x10020600, EMI dates 0x683x0; MT6359 rails by HWCID |
| 85c4941 | PMIC wrapper commands under the shared `begonia_pwrap_take` lock (an interleaved read was seen) |
| c765cfd | `begonia_wifi_rails=2`: VCN33_1 selector 3.5 V -> 3.3 V while the rail is off (the user's approval), restored on off |
| 70cd3db | the MCU ROM patch `soc1_0_patch_mcu_2a_1_hdr.bin` over WMT in PDA mode at 0x1C000, then `wmt reset` (calibration was never answered without it) |
| e3740a4 | init events: 16-byte RX descriptor on gen4m "connac" (not 20) |
| 7a51e32 | worker polls every 10 ms (not 2) when joined and quiet |

PMIC writes happen only with `begonia_wifi_rails=1|2`; without it the driver reads and stops. Sources used (MediaTek's
MT6785 connectivity code, from LineageOS android_kernel_xiaomi_mt6785) are kept outside the repository.

## Safari: pages, then their icons

- Black pages: WebKit's helper processes (`com.apple.WebKit.GPU`, `com.apple.WebKit.WebContent`) live in
  WebKit.framework/XPCServices, not in an `.app`, so `@apps` did not show them the Metal device. They are named in the
  Metal clients now.
- Missing icons/logos (SVG, curved paths): WebKit's tiles are drawn by CoreGraphics in `CGIOSurfaceContext`, which
  draws through Metal with QuartzCore's `com.apple.coreanimation.draw.*` shaders; those use framebuffer fetch, which
  metal2vulkan refused (PanVK v7 has neither raster-order attachment access nor pixel interlock). Fixed by bridge
  patch `userland/metal/bridge/patches/0002` (`FramebufferFetchPolicy::AcceptUnordered`) and runtime patch
  `userland/metal/runtime-patches/0001` (a fetching draw the exact serialization cannot split is drawn unordered
  instead of refused). `tests/cg_shapes_test` (every shape, CPU bitmap vs IOSurface context) went from most shapes
  empty to all matching; google.com draws its logo and icons (y72); Freeform's pen draws (y73).

## Bold Text

Turning it on crashed SpringBoard at every start (and it could not be turned off): CoreUI's text effects go through
CoreImage, which, with no Metal device in SpringBoard, took its OpenGL ES path and called through an empty function
table (CoreImage+0x19c58c, `entry(rend, GL_DEPTH_TEST)`, pc 0). Fixed by showing SpringBoard the Metal device (y76: no
crash, Settings in bold). Taking EAGLContext away and forcing CoreImage's software renderer did not help (y74, y75).
`prefs_aside=NAME` (init patch 0037) moves a crashing preference aside before launchd; `ax_bold=0|1` (0039) sets the
setting for tests.

## Idle CPU (cpu_idle_test, 30 s untouched)

y77: 27% of one core in all: the kernel 12.4% (polling drivers: the touch driver's 1 MHz SPI read, ~650 us with
interrupts off every 8 ms, was ~7.5%), backboardd 6.4% (compositing ~60 frames a second for animated content),
runningboardd 2.1%, the weather widget 1.7%. Touch now polls every 20 ms once no touch came for a second.
The larger heat sources are not idle polling: CPU and GPU run at fixed maximum clocks and voltages from boot (no
scaling down), and compositing on OpenGL ES is CPU-heavy while anything moves.
