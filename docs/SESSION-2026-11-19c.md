## The purple

PaperBoardUI gives every "fake blur" (the upper part of the screen in one-handed mode, the wash over the switcher's
cards) the wallpaper's snapshot, `.../PRBPosterExtensionDataStore/.../RuntimeSnapshot-home.atx`. On this phone that
picture is magenta from corner to corner (y5: 255,0,255 in every part): whatever renders the poster for the snapshot
has nothing to render with here. Userland 0030 makes the two snapshot sources (`PBUIBakedEffectSnapshotSource`,
`PBUIURLBackedSnapshotSource`) answer with a picture of the wallpaper as it is on the panel: taken once with the icons
and the status bar hidden for under half a second, kept in `/var/mobile/Library/hakios-wallpaper.raw` and `.name`, and
taken again only when the snapshot's name changes (another wallpaper). The live wallpaper is not touched.
`wallpaper_snapshot=0` turns it off.

## Metal

- **What there was.** Today's images had no Metal at all: the window server draws through OpenGL ES (Mesa/Panfrost)
  and an application gets nil from `MTLCreateSystemDefaultDevice`. `STATE.md` (6 and 7 November, built on a Mac)
  records the Metal stack running on this phone: PanVK, metal2vulkan, the `HakiosMetal` bundle of the S9+ reference.
  None of its binaries were on this PC.
- **Built here, under WSL** (new scripts, ports of the macOS ones):
  `tools/build_panvk_linux.sh` (Mesa 26.2.6 at 8e87a503: host tools `mesa_clc`, `vtn_bindgen2`, `panfrost_compile`,
  then the cross build; Meson 1.7 run from `.tools/meson-src`), `tools/build_metal2vulkan_linux.sh` (Rust 1.98.1 with
  `aarch64-apple-ios` in `.tools/rust`, linked by xnu-clang), `tools/build_metal_frontend_ios.py --cc xnu-clang
  --experimental-mps-stubs`, `tools/build_gpu_tests_linux.sh`. Sources needed under `upstream/`: `mesa-vulkan`,
  `metal2vulkan` at 720ef1ce, `viva-gpu` at ab2a1b43 (headers).
- **Staged** by `tools/make_gles_support.py --metal-client NAME` (fifth argument of `auto_build.sh`, fourth of
  `y_cycle.sh`): the two libraries stripped into `lib/`, the bundle and `HakiosMetal.clients` into `ext/`, the tests
  into `bin/` and run late in the session. Boot argument `metal=1`: the kernel names the plug-in, and with level 1
  only the programs in `HakiosMetal.clients` are shown the device; the window server stays on OpenGL ES.
- **Two things that were in the way.** The boot partition is 64 MB and the image with both libraries did not fit
  (y21): the runtime is built for size (`CARGO_PROFILE_RELEASE_OPT_LEVEL=s`, `LTO=fat`, `CODEGEN_UNITS=1` into
  `out/metal2vulkan-target-ios-small`), and the image is now 66.5 of 67.1 MB: there is almost no room left. And the
  system volume has no `Extensions/HakiosMetal.bundle`: a union mount from init did not show it (removed again);
  kernel patch 0018 names the plug-in `../../../redwood/ext/HakiosMetal`, which Metal resolves from
  `/System/Library/Extensions/` into the support image (y24).
- **Freeform with the device.** It aborts at launch, in
  `-[CRLMetalShader p_createPipelineStateWithRenderPipelineDescriptor:device:setupArguments:]`: "Failed to create
  pipeline reflection object" (the abort's callers placed in the binary by the spacing of their call sites; slide
  0x40c000 in y25). The front end answers every pipeline's reflection with nil
  (`NativeBridgeMetalFrontend.mm`, `if(reflection)*reflection=nil;`). Freeform reads from it the index and size of
  its uniform buffers and the index of its sampler (`p_indexOfUniformsFromMetalArguments:size:bufferIndex:`).
- **Next step for Freeform:** the runtime has the facts (`RenderPipelineState::reflection()` in
  `metal2vulkan/src/reflection/mod.rs`: bindings with name, type, access, index, used; buffer alignment and size;
  texture type). They need a function in the C bridge (`NativeMetalObjects.rs`) and objects in the front end that
  answer `vertexArguments`/`fragmentArguments` (and `vertexBindings`/`fragmentBindings`).
- **What this is not.** A device that passes a clear and a blit is the first step of several for applications, and a
  long way from games: every shader a game brings must translate, every Metal feature it uses must exist in the
  front end, and it must be fast. The record of 7 November had SpringBoard itself on this path at about 6 frames a
  second.

Freeform's own way of drawing brushes without Metal was tried first (its `isMetalCapable`, `p_isMetalCapable` and
`brushStrokeUsesMetal` answered no, y20): the strokes were recorded and not drawn. Reverted.

## Control Centre

The stripes are there in a scripted session (y12) and are not from sharing text masks (`glmask=0`, y13: the same).
CoreAnimation does not use Apple's `GL_UNPACK_ROW_BYTES_APPLE` here (y15: only alignment and row length were ever
set); userland 0033 keeps that name correct anyway and 0034 says the kinds of upload with every summary. No upload of
a new kind happens when Control Centre opens, so the glyphs do not come through `glTexImage2D` at that moment. Open.

## Tools added

- Colour shots: `fb_shot_rgb=1` (kernel 0015: twelve bits a pixel, a row in two lines `SHOCn NNNa/b`), and a shot
  when the script asks: `notify com.hakios.shot` (sysctl `kern.hakios.fb_shot_now`, taken at once: a still screen
  has no next frame). `shot.py LOG PREFIX [SCALE]` reads both kinds.

  `com.hakios.open.freeform`, `.safari`, `.settings`, `com.hakios.front` (which application is in front),
  `com.hakios.pbui` (PaperBoardUI's classes and wallpaper views).
- `y_cycle.sh TAG " args" SCRIPT [METAL CLIENTS]`: a cycle, the shots as pictures, the lines that matter.
- Kernel 0016 also keeps Freeform's aborts with the notes.
- `tools/place_return_chain.py BL-LINES f1 f2 ...`: places a chain of return addresses in a binary
  whose load address is not known.

## What cost time

- The log ring holds the last 25 seconds or so of a session (uptime 62 to 87 s): an action before that leaves
  nothing. The script's clock starts 5 to 10 s after the kernel's and not the same every boot: shots by
  notification, not by `fb_shot=SECONDS`.
- A line of the log keeps about 250 characters; a longer one loses its end and its line break.
- The owner's own touches during a scripted session spoil the shot; the session is simply run again.
- An application's `NSLog` reaches no log that is kept; the Metal front end now says its problems on the console too
  (`metal: NAME[pid]: ...`).
